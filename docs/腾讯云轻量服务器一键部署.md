# 腾讯云轻量应用服务器一键部署（无 NAS 用户）

适合「愿意自部署、但没有 NAS」的朋友：买一台最便宜的轻量服务器，粘贴一条命令，装完即用。全程约 5 分钟。

---

## ⚠️ 部署前必读：安全与隐私须知

把 SubDeck 装到云服务器上 = 把数据放到**公网上的一台机器**里。和放在家里内网的 NAS 不同，以下风险真实存在，**决定部署前请逐条读完；继续部署即视为已知悉并接受**。

### 1. 传输是明文 HTTP，密码和数据不加密

脚本默认让你用 `http://服务器IP:端口` 访问，**没有 HTTPS**。这意味着：

- 登录密码、订阅内容在公共网络中明文传输，链路上的任意节点（运营商、公共 Wi-Fi 出口、中间设备）理论上可以截获内容；
- 脚本自动生成的随机密码强度足够，但**挡不住明文传输本身**。

如果你对隐私要求高（例如记录了收入相关订阅、不想让任何人有截获机会），两个补救方向：

- **配域名 + HTTPS**：大陆地域的服务器绑域名走 80/443 需要 ICP 备案；不想备案可以选香港/境外地域，但延迟略高。配好反向代理后请把 compose 的端口映射改回仅监听 127.0.0.1；
- **降低暴露面**：把防火墙来源限制为常用 IP 段（腾讯云防火墙支持设置来源），或只在需要时临时放行端口。

### 2. 访问密码是唯一防线

SubDeck 是单用户自部署设计：**一把密码，无二次验证、无登录尝试限制**。

- 密码泄露 = 数据泄露 = 任何人可增删改你的订阅记录；
- 请使用脚本自动生成或自行提供的强密码，不要改成 `123456` 这类弱密码；
- 任何在浏览器里保存密码的习惯风险自负。

### 3. 数据存在云服务器磁盘上

订阅数据（SQLite 数据库、上传的 logo、登录密钥）全部存在服务器的 `data/` 目录：

- 云服务商对宿主机磁盘有物理层面的访问能力，这是所有云主机的共同属性；
- **退订或重装服务器前，先备份 `data/` 目录到本地，再自行彻底删除**，避免数据残留在被回收的磁盘上；
- 服务器被入侵的最常见原因不是 SubDeck，而是弱 SSH 密码和过时的系统补丁——请保持系统更新，密码方式登录 SSH 的建议改用密钥。

### 4. 公网扫描是常态，端口只开一个

服务器一上线就会被自动化扫描器盯上。脚本部署只要求开放一个 TCP 端口（默认 8300），**请勿在防火墙开放 Docker 管理端口（2375/2376）或其他无关端口**。

### 5. 维护是部署者的责任

- 升级：`cd /opt/subdeck && docker compose pull && docker compose up -d`（建议每月一次，安全修复随镜像发布）；
- 备份：定期拷贝 `/opt/subdeck/data` 目录；服务器坏了数据不负责自动恢复；
- 免责说明：SubDeck 以「按现状」提供（MIT 许可证，见仓库 LICENSE），因部署、维护、服务器故障导致的数据丢失或泄露，需由部署者自行承担。

### 6. 关于备案

- 只用 `http://IP:端口` 访问：**不需要备案**；
- 绑定域名通过 80/443 访问大陆地域服务器：需要 ICP 备案（域名备案流程请走腾讯云官方渠道，个人可办）。

## 部署步骤

### 第 1 步：买一台轻量服务器

腾讯云控制台 → 轻量应用服务器 → 创建实例。建议配置：

- **地域**：就近选（大陆地域延迟低，用 IP 访问不需备案；在意隐私可选香港）
- **镜像**：Ubuntu Server 24.04 LTS（22.04 也行）
- **套餐**：最低配即可（2C2G 足够，SubDeck 很轻）
- 新用户常有 ¥50~100/年的促销套餐，比一杯奶茶贵不了多少

### 第 2 步：粘贴安装命令

创建完成后，进入实例详情 → 「概要」页找到 **网页终端（OrcaTerm）** 点「登录」（默认 root 免密或按提示设置），在终端里粘贴：

```bash
curl -fsSL https://cdn.jsdelivr.net/gh/sinailurus/subdeck@main/install.sh | bash
```

> jsdelivr 打不开时，两种替代：① 从 [install.sh](../install.sh) 页面复制全文，粘贴到终端回车；② 走 GitHub 原始地址：`curl -fsSL https://raw.githubusercontent.com/sinailurus/subdeck/main/install.sh | bash`

可选参数（想自定义时用）：

```bash
# 指定端口和密码
curl -fsSL https://cdn.jsdelivr.net/gh/sinailurus/subdeck@main/install.sh | bash -s -- --port 8300 --password 你的强密码
```

脚本会自动：装 Docker → 生成随机密码（未指定时）→ 写配置到 `/opt/subdeck` → 拉镜像（国内走南大中转，失败自动切官方源）→ 启动并自检。

### 第 3 步：开防火墙端口（必须手动做）

**不开防火墙规则，外网永远访问不了**。腾讯云控制台 → 轻量应用服务器 → 你的实例 → 「防火墙」页 → 添加规则：

| 字段 | 填写 |
|---|---|
| 应用类型 | 自定义 |
| 协议 | TCP |
| 端口 | 8300（或你 `--port` 指定的） |
| 来源 | `0.0.0.0/0`（或你的常用 IP 段，更安全） |

### 第 4 步：登录

浏览器打开脚本最后打印的 `http://服务器IP:端口`，输入访问密码（脚本会打印一次，同时保存在 `/opt/subdeck/.env`，忘了可用 `cat /opt/subdeck/.env` 查看）。

## 常用操作

```bash
cd /opt/subdeck

# 查看日志
docker logs -f subdeck

# 升级到最新版（数据不受影响）
docker compose pull && docker compose up -d

# 备份数据
tar czf ~/subdeck-backup-$(date +%F).tar.gz data/

# 修改密码或端口：编辑 .env 后重启
nano .env && docker compose up -d
```

## 迁移与退订

- **迁回 NAS**：拷走 `data/` 目录 → 在 NAS 的 compose 里把 `SUBDECK_DATA` 指到该目录 → 启动即可，登录密钥随密钥文件保留；
- **退订前**：先备份 `data/`，再删掉服务器上的 `/opt/subdeck`，确认清干净后再退订。

## 常见问题

**Q：装完访问不了？**
九成是防火墙没开端口（看第 3 步），剩下检查命令是否以 root 跑完、`docker logs subdeck` 有无报错。

**Q：端口被别的程序占了？**
`--port 8888` 换一个，同时在防火墙页放行新端口。

**Q：想绑域名 + HTTPS？**
先过一遍上方「安全与隐私须知」第 1 条和第 6 条：大陆地域需备案，然后自备 Caddy/Nginx 反向代理，并把 compose 端口映射改为 `127.0.0.1:8300:8000` 只监听本机。
